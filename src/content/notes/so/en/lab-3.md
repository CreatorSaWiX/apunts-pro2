## Block 1: Fundamental System Calls

| Call | Manual Section | Return Value | Typical Usage |
| :--- | :---: | :--- | :--- |
| **`fork()`** | `man 2` | `0` to child, `PID` to parent, `-1` on error | Duplicates current process. |
| **`getpid()`** | `man 2` | `pid_t` (own PID) | Identity query. |
| **`getppid()`** | `man 2` | `pid_t` (parent's PID) | Creator query. |
| **`exit(code)`** | `man 3` | Does not return | Terminates process and transitions to `Z (zombie)`. |
| **`waitpid(pid, &st, opts)`** | `man 2` | Terminated child PID | Awaits child and reaps its PCB. |
| **`execlp(file, a0, ...)`** | `man 3` | **Only on failure** (`-1`) | Replaces process memory image. |
| **`perror(msg)`** | `man 3` | `void` | Writes kernel error (`errno`) to `stderr` (channel 2). |

:::shellviz{command="man 2 fork" suggestions="man 2 fork,man 2 waitpid,man 3 perror" title="Terminal — Consult system call manual pages"}

## Block 2: Error Handling with `perror`

Mandatory pattern for calls that may fail:

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void error_y_exit(char *msg, int exit_status) {
    perror(msg);
    exit(exit_status);
}
```

## Block 3: Process Creation and Mutation (`myPS.c`)

```c
void muta_a_PS(char *username) {
    execlp("ps", "ps", "-u", username, (char *)NULL);
    error_y_exit("Mutation to ps failed", 1);
}
```

### Question 29: Obtaining PIDs
* **How does the parent know the children's PIDs?** Through the **return value of `fork()`** (returns positive PID of the child to parent; returns `0` to child).
* **How does a process inspect its own PID?** Using the system call **`getpid()`** (and `getppid()` for the parent PID).

### Question 30: Execution after `execlp`
* **Under what circumstance is the code following `execlp` executed?** **ONLY IF EXECLP FAILS**.
* **Reason:** If `execlp` succeeds, the kernel completely replaces the entire process address space with the new binary. Original code ceases to exist in RAM. If the subsequent line executes, it is definitive proof that mutation failed.

:::shellviz{command="./myPS alumne" suggestions="./myPS alumne,which ps,ps -u alumne" title="Terminal — Execution of myPS mutating into ps"}
:::

## Block 4: The `/proc` Pseudo-Filesystem (Q31 to Q36)

`/proc` is an in-memory virtual filesystem generated by the Linux Kernel.

### Question 31: Files in `/proc/[PID]/`
* Command to list links and metadata: `ls -la /proc/$$/` (`$$` = current PID).
* **Key files**:
  * `status`: Scheduler state (`State:`), memory (VmSize), and UIDs.
  * `cmdline`: Command invocation arguments separated by null bytes `\0`.
  * `environ`: Environment variables inherited at process launch.
  * `cwd`: Soft link pointing to the current working directory.
  * `exe`: Soft link pointing to the executable binary on disk.

:::shellviz{command="ls -la /proc" suggestions="ls -la /proc,df -h" title="Terminal — Exploring the /proc filesystem"}
:::

### Question 32: Comparison of `environ` and States
* `/proc/[PID]/environ` contains the exact same list of variables as the `env` command.
* **Process states in the `State` field**:
  * Process in active loop `while(1);` $\rightarrow$ **`R (running)`**.
  * Process waiting in `waitpid()` $\rightarrow$ **`S (sleeping)`**.
* **CPU Time**: Field 14 in `/proc/[PID]/stat` (*utime*).

### Questions 33 to 36: `cwd`, `exe`, and Mutation
* `cwd`: Inherited from parent; `exec` **does not** change it.
* `exe`: In an unmutated process (`myPS_v0`), points to `./myPS_v0`. Upon mutating with `execlp("ps", ...)` (`myPS`), `exe` points to `/usr/bin/ps`.

## Block 5: Sequential Execution (`myPS2.c`)

The parent spawns children **one by one**, waiting for each before spawning the next:

```c
for (int i = 0; i < num_fills; i++) {
    int pid = fork();
    if (pid < 0) error_y_exit("Error fork", 1);
    if (pid == 0) {
        muta_a_PS(argv[i + 1]);
    }
    // Parent WAITS INSIDE the loop: 100% deterministic order
    waitpid(pid, NULL, 0);
}
```

:::

## Block 6: Concurrent Execution (`myPS3.c`)

The parent **spawns all children immediately** and reaps them afterward:

```c
// 1. Concurrent spawning phase
for (int i = 0; i < num_fills; i++) {
    int pid = fork();
    if (pid < 0) error_y_exit("Error fork", 1);
    if (pid == 0) {
        muta_a_PS(argv[i + 1]);
    }
    // Parent does NOT wait here
}

// 2. PCB reaping phase
while (waitpid(-1, NULL, 0) > 0);
```

### Question 37: Parent State During Wait
* The parent is in state **`S (sleeping)`** because `waitpid(-1, ...)` is a **blocking** system call that yields CPU time.

### Question 38: Non-determinism
* Running `./myPS3 alumne root > sortida.txt` multiple times may produce differing output orders because execution interleaving depends on the kernel scheduler.

:::shellviz{command="./myPS3 alumne root > sortida1.txt" suggestions="./myPS3 alumne root > sortida1.txt,cat sortida1.txt" title="Terminal — Redirecting concurrent output to file"}
:::
