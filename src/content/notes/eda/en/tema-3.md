## 3.1. Abstract Data Types (ADT)

An **ADT** specifies data structure *behavior* independently of concrete implementation details: **knowing the *what* without knowing the *how*.**
Formally, an ADT is defined by three elements: admissible **values**, operational **signatures**, and equational **axioms** relating the operations.

:::tadviz
:::

**Boolean ADT** — Values: $\text{Bool} = \{\text{true}, \text{false}\}$; Operations: $\text{and}, \text{or}, \text{not}$; Axioms:
$$\text{and}(\text{true}, x) = x, \quad \text{and}(\text{false}, x) = \text{false}, \quad \text{or}(\text{true}, x) = \text{true}, \quad \text{not}(\text{true}) = \text{false}$$

**Integer ADT** — Values: $\mathbb{Z}$ (in hardware, $[-2^{31}, 2^{31}-1]$ in 32-bit two's complement); Operations: $+, -, \times, /, \%$; Axioms: $a + 0 = a$, $a \cdot 0 = 0$, overflow behaviors, etc.

**Natural Number ADT (Peano)** — Values: $\mathbb{N}$ generated by $\text{zero}$ and $\text{succ}$; Axioms:
$$\text{add}(\text{zero}, x) = x, \quad \text{add}(\text{succ}(x), y) = \text{succ}(\text{add}(x, y))$$

## 3.2. The Dictionary ADT

A dictionary stores associations of **(key, value)** pairs ($k \in K$, $i \in I$) and provides efficient manipulation primitives:

* **Unique Keys:** Duplicate keys are prohibited; assigning an existing key overwrites its associated payload.
* **Key-based Access:** Queries and deletions index strictly on the key attribute, never on values.
* **Many-to-one Mapping:** Multiple distinct keys may bind to identical payload values.

:::dictviz
:::

### Operations 
* **`assign(k, v)` / `insert`:** Inserts pair $(k, v)$ or updates existing key $k$.
* **`erase(k)`:** Removes element indexed by key $k$.
* **`find(k)`:** Returns value associated with key $k$ (or signals non-existence).
* **`contains(k)` / `count`:** Queries whether key $k$ resides in dictionary.
* **`size()`:** Returns element count.

## 3.3. Elementary Dictionary Implementations

On a collection of $n$ records, linear sequence structures manifest unavoidable scaling bottlenecks:

| Structure | Assign | Erase | Find | Structural Bottleneck |
| :--- | :---: | :---: | :---: | :--- |
| **Unsorted Vector** | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ | Must scan full buffer to verify key uniqueness. |
| **Unsorted Linked List** | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ | No random access; forced linear traversal. |
| **Sorted Vector** | $\Theta(n)$ | $\Theta(n)$ | $\Theta(\log n)$ | Binary search $\Theta(\log n)$, but insertion shifts $\Theta(n)$ items. |
| **Sorted Linked List** | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ | Ordered but lacks indexing; binary search impossible. |

**$\Theta(1)$ Unsorted Vector Deletion Trick:** copy the final element into the erased slot and invoke `pop_back()`. Avoids linear shifting but disrupts element order.

## 3.4. Hash Tables

**Hash tables** achieve expected constant time $\Theta(1)$ for lookup, insertion, and deletion, with worst-case cost $\Theta(n)$ under catastrophic collisions.

### Direct Addressing Tables

The simplest dictionary implementation uses keys directly as vector indices: `T[key] = value`, giving $\Theta(1)$ access.

If keys span huge domains (such as 8-digit government IDs) while only 300 active users exist, allocating a vector of $10^8$ buckets (100 million entries!) wastes unsustainable RAM capacity.

:::directaddressviz
:::

### The Hash Function

To resolve this, we allocate a table $T$ with bounded capacity $m$ (proportional to expected element counts) and map keys into valid slot indices via a **hash function $h$**:

$$
\text{slot} = h(\text{key}) \quad (\text{range } [0, m-1])
$$

The element is stored in slot `T[h(key)]`.

:::hashviz
:::

Desired properties of effective hash functions:
1. **Deterministic:** Identical keys must evaluate to identical bucket indices.
2. **Fast Evaluation:** Computing $h(\text{key})$ must execute in constant time $\Theta(1)$.
3. **Uniform Distribution:** Disperses keys uniformly across buckets to avoid clustering.

### Collisions

Because the universe of keys is substantially larger than table capacity $m$, distinct keys eventually map to identical bucket slots ($h(k_1) = h(k_2)$).

:::collisionviz
:::

This phenomenon is a **collision**, requiring systematic conflict resolution (such as separate chaining and open addressing).

---

### Collision Resolution via Separate Chaining

Each bucket $T[j]$ maintains an independent **linked list** of all colliding records with $h(k) = j$.

:::chainingviz
:::

The **load factor** $\alpha = n/m$ represents average chain length:

| Case | Cost | Precondition |
| :--- | :---: | :--- |
| **Worst** | $\Theta(n)$ | All $n$ keys hash to the identical bucket. |
| **Average** (Simple Uniform Hashing) | $\Theta(1 + \alpha)$ | Keys distribute uniformly across slots. |
| **Average with $m = \Theta(n)$** | $\Theta(1)$ | Sizing $m \propto n$ ensures $\alpha = \mathcal{O}(1)$. |

---

### Collision Resolution via Open Addressing

Unlike separate chaining, open addressing maintains **no external linked nodes**: all elements reside directly within primary table slots ($n \le m$).

When insertion encounters an occupied slot (collision), the algorithm searches for alternative empty slots via a systematic probe sequence:

:::openaddressviz
:::

| Strategy | Probe Sequence | Trade-offs |
| :--- | :--- | :--- |
| **Linear Probing** | Inspects adjacent slot: $+1, +2, +3, \dots$ | **Very simple**, but suffers from **primary clustering** (consecutive filled runs slow lookups). |
| **Quadratic Probing** | Jumps quadratically: $+1^2, +2^2, +3^2, \dots$ | Breaks continuous clustered runs, though identical initial hashes follow identical paths. |
| **Double Hashing** | Step size computed by secondary hash: $+1 \cdot h_2(k), +2 \cdot h_2(k), \dots$ | **Optimal dispersion**: colliding initial hashes diverge across completely distinct probe paths. |

## 3.5. Trees: Terminology and Definitions

A **tree** is an acyclic hierarchical structure composed of vertices and edges. In a **rooted tree**, a distinguished node serves as the **root** $r$.

:::treeterviz
:::

* **Root:** Topmost node lacking a parent.
* **Parent & Children:** Nodes linked directly along downward hierarchy.
* **Leaves:** Terminal nodes bearing zero children.
* **Ancestors & Descendants:** Paths upward (toward root) or downward (toward leaves).
* **Height ($h$):** Longest edge path from root to any leaf.

### Binary Trees

A **binary tree** restricts each node to at most two direct descendants: a **left child** (`left`) and a **right child** (`right`).

## 3.6. Binary Search Trees (BST)

A **BST** implements the dictionary ADT relying on a **total order** over keys.

### The BST Invariant Property

For any node $x$ with key $k_x$:
* All keys in the **left subtree** are strictly $< k_x$.
* All keys in the **right subtree** are strictly $> k_x$.

:::abcviz
:::

> **Core Exam Theorem:** An **in-order traversal** (Left → Root → Right) of a BST outputs keys in **strictly increasing order**.

:::oopviz{simulation="diccionari_abc"}
:::

---

### Core BST Operations

* **Search ($\Theta(h)$):** Compares target against current node, branching left if smaller or right if larger.
::algoviz{algorithm="abc_cerca"}

* **Insertion ($\Theta(h)$):** Traverses the tree; if key exists, updates payload; if a null child pointer is reached, attaches new leaf.
::algoviz{algorithm="abc_assignar"}

* **Minimum & Maximum ($\Theta(h)$):** The minimum is the leftmost node; maximum is the rightmost node.
::algoviz{algorithm="abc_minim_maxim"}

* **Deletion ($\Theta(h)$):** Case distinctions based on degree:

| Case | Removal Strategy |
| :--- | :--- |
| **0 children (leaf)** | Deleted directly (parent pointer reset to `nullptr`). |
| **1 child** | Parent splices directly to the surviving child. |
| **2 children** | Spliced with its **in-order successor** (minimum of right subtree, with degree $\le 1$). |

:::oopviz{simulation="diccionari_esborrar"}
:::

---

### Height Degeneration in BSTs

The time cost of all BST primitives scales directly with height $h$:

$$
T_{\text{find}},\; T_{\text{insert}},\; T_{\text{erase}} \in \Theta(h)
$$

* **Average Case (random insertion):** Generates balanced trees with $h = \Theta(\log n)$.
* **Worst Case (sorted input $1, 2, 3 \dots$):** Degenerates into a linear linked list with height $h = n-1$, degrading operations to linear time **$\Theta(n)$**.

:::abcdegenviz
:::

## 3.7. Self-Balancing Trees: AVL Trees

To prevent pathological degeneration to $\Theta(n)$, **AVL trees** enforce a rigid balance invariant restored dynamically upon insertions and deletions.

### Definition of an AVL Tree

An **AVL tree** is a BST where, **for every node**, subtree heights differ by at most 1:

$$
|\text{height}(\text{left}) - \text{height}(\text{right})| \le 1
$$

> **Height Guarantee:** This invariant ensures maximum height bounded by $h \le 1.44 \log_2 n$. Hence, height is strictly **$h = \Theta(\log n)$ in the worst case**.

:::oopviz{simulation="diccionari_avl"}
:::

---

### Rotations in AVL Trees

When an update induces an imbalance ($\text{balance} = \pm 2$), a **local rotation in constant time $\Theta(1)$** restores balance invariants while preserving in-order traversal:

| Case | Imbalance Configuration | Balancing Rotation |
| :--- | :--- | :--- |
| **LL** | Insertion into left child of left child | **Right Single Rotation** (`LL`) |
| **RR** | Insertion into right child of right child | **Left Single Rotation** (`RR`) |
| **LR** | Insertion into right child of left child | **Double Rotation:** Left on child + Right on node |
| **RL** | Insertion into left child of right child | **Double Rotation:** Right on child + Left on node |

:::avlrotviz
:::

::algoviz{algorithm="avl_ll"}

::algoviz{algorithm="avl_rr"}

::algoviz{algorithm="avl_lr"}

---

### Insertion vs Deletion in AVL Trees
* **Insertion ($\Theta(\log n)$):** Node is placed as in a BST; during upward backtracking, rebalancing occurs. **At most 1 rotation** (single or double) is required to rebalance the entire tree.
::algoviz{algorithm="avl_assignar"}

* **Deletion ($\Theta(\log n)$):** Node is spliced as in a BST. Retracing to the root may require **up to $\mathcal{O}(\log n)$ rotations** cascading upward.
::algoviz{algorithm="avl_esborrar"}

## 3.8. Comprehensive Summary of Dictionary Complexities

| Data Structure | Search | Insertion | Deletion | In-Order Traversal | Notes |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **Unsorted Vector** | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n \log n)$ | Viable only for small collections ($n < 20$). |
| **Sorted Vector** | $\Theta(\log n)$ | $\Theta(n)$ | $\Theta(n)$ | $\Theta(n)$ | Optimal for static read-heavy datasets. |
| **Hash Table** | $\Theta(1)$\* | $\Theta(1)$\* | $\Theta(1)$\* | Not supported | Fastest in practice without ordering requirements. \*Worst case $\Theta(n)$. |
| **BST** | $\Theta(\log n)$\* | $\Theta(\log n)$\* | $\Theta(\log n)$\* | $\Theta(n)$ | Can degenerate to $\Theta(n)$ on sorted inputs. \*Average case. |
| **AVL / RB (`std::map`)** | $\Theta(\log n)$ | $\Theta(\log n)$ | $\Theta(\log n)$ | $\Theta(n)$ | **Guarantees $\Theta(\log n)$ in worst case** with sorted iteration. |
