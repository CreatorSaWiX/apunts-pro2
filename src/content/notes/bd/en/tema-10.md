### THIS TOPIC IS NOT ON THE FINAL EXAM

**NoSQL** (*Not Only SQL*) encompasses non-relational database systems designed for large volumes of distributed data, high query speed, and flexible schemas.

---

## 10.1. Context: OLTP, OLAP, and NoSQL

| DB type | Data and primary workload | Typical model |
| :--- | :--- | :--- |
| **Operational (OLTP)** | Structured data, daily operations, and concurrent transactions. | Relational model (SQL). |
| **Analytical / Decision (OLAP)** | Mainly massive reads for analysis and forecasting (*Data Warehousing*). | Analytical / columnar storage. |
| **NoSQL** | Semi-structured or unstructured data at large scale (web, social networks). | Key-value, column, document, graph. |

- **The end of *"One size fits all"*:** not all problems are best solved using only traditional relational DBMSs; *"NoSQL"* means *Not Only SQL* (not *never SQL*).
- **Common NoSQL traits:** massive data volumes, replication and distribution across thousands of nodes, asynchronous updates, high read efficiency, and lack of a predefined schema (*schema-less*).

---

## 10.2. CAP theorem and BASE model (vs. ACID)

### CAP theorem

In a distributed system there are three properties: **C** (*Consistency* — all nodes see the same data), **A** (*Availability* — every request receives a response), and **P** (*Partition tolerance* — the system operates despite network communication cuts between nodes).

- When an inevitable network partition occurs, **both `C` and `A` cannot be guaranteed simultaneously**: one must choose between returning an error to protect data (**CP**) or continuing to serve requests at the risk of temporary inconsistency (**AP**).
- Traditional NoSQL databases prioritize **availability (`AP`)** over immediate consistency.

### ACID vs. BASE

| Property / Approach | **ACID** (Relational) | **BASE** (NoSQL) |
| :--- | :--- | :--- |
| **Meaning** | **A**tomicity, **C**onsistency, **I**solation, **D**urability. | **B**asically **A**vailable, **S**oft state, **E**ventually consistent. |
| **Consistency** | Strong and immediate (safe transactions). | Weak / eventual (changes propagate asynchronously). |
| **Priority** | Data integrity and reliability. | Availability and performance (accepts approximate responses, optimistic). |

## 10.3. The 4 NoSQL database models

| Model | Data structure | Key characteristics |
| :--- | :--- | :--- |
| **Key-Value Stores** | Flat `<Key, Value>` pairs. | Only `get` / `set` / `delete` operations by key; the application interprets the value (often JSON). |
| **Wide-Column Stores** | Tables of **column families** (*2-level Key-Value*). | Each row can have different columns and formats without a rigid schema. |
| **Document-Stores** | `<Key, Doc>` pairs (JSON or XML). | Allows querying and indexing by the **internal content** of the document; many add extended SQL and ACID. |
| **Graph Databases** | **Nodes** and **edges** with properties. | Ideal for highly connected semi-structured information (social networks, routes). |

## 10.4. Relational vs. NoSQL and trends

| Criterion | Relational DBs (RDBMS) | NoSQL DBs |
| :--- | :--- | :--- |
| **Schema** | Predefined (`CREATE TABLE` / `ALTER TABLE`). | No fixed schema (*schema-less*). |
| **Language** | Declarative standard SQL (*what*, not *how*) with optimizer. | Product-specific APIs or query languages. |
| **Consistency** | Strong (`ACID`, DDL constraints, and triggers). | Eventual (`BASE`), prioritizing availability and horizontal scalability. |

- **The cost of giving up the relational model:** without an SQL compiler/optimizer or ACID guarantees in the engine, access logic and data consistency fall onto the **application code**.
- **Current trends:**
  - NoSQL vendors adding **ACID transactions** and **SQL** (or similar dialects).
  - **Multi-model systems:** a single DBMS combines models (e.g., PostgreSQL supports the relational model and `JSON` documents).
  - **Columnar relational DBs:** store by columns instead of rows to speed up analytical queries.
  - **Vector databases:** store *embeddings* (numerical vectors generated by AI models) for fast **semantic similarity** searches (documents, images, recommendations).
